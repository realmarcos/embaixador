# Data Model: Download de Mídias Online

## Account

Represents an authenticated user. Extend the existing `User` domain rather than
creating a second account model.

| Field | Type | Rules |
|---|---|---|
| `id` | UUID/string | Primary key; generated by the persistence boundary. |
| `name` | string | Required; retain existing user contract. |
| `email` | string | Required, normalized, unique. |
| `passwordHash` | string | Required; store only a one-way `scrypt` hash with unique salt and encoded parameters, never the password. Verify with constant-time comparison. |
| `avatar` | string, nullable | Preserve current domain field if used by the UI. |
| `themePreference` | enum | `LIGHT` or `DARK`; default `LIGHT`. |
| `retentionHours` | integer enum | One of `1`, `8`, `24`, `72`, `168`, `336`, `720`; default `1`. |
| `createdAt`, `updatedAt` | datetime | UTC timestamps. |

**Relationships**: One account owns zero or more download/history records.

**Validation**: Normalize email before uniqueness checks; reject unsupported
theme or retention values; exclude `passwordHash` from all public DTOs.

## Download

One row represents both a requested download job and its history entry. The row
remains after a media file is manually deleted or expires.

| Field | Type | Rules |
|---|---|---|
| `id` | UUID/string | Primary key; opaque identifier. |
| `userId` | UUID/string | Required owner foreign key; indexed with `createdAt`. |
| `platform` | enum | `YOUTUBE`, `INSTAGRAM`, or `FACEBOOK`. |
| `sourceUrlCiphertext`, `sourceUrlIv`, `sourceUrlTag`, `sourceUrlKeyVersion` | strings | Required for history re-download; encrypt canonical source URL with authenticated encryption and a secret managed outside the database. Never log plaintext. Reject URL credentials and strip nonessential tracking parameters before encryption. |
| `title` | string, nullable | Sanitized display metadata only; no full extractor payload. |
| `selectedFormatId` | string | Provider-returned option selected by the user; revalidated by the provider at download time. |
| `targetContainer`, `targetHeight` | string/integer, nullable | Selected output format and requested dimensions when available. |
| `status` | enum | `QUEUED`, `PROCESSING`, `READY`, `FAILED`, `MEDIA_DELETED`, `EXPIRED`, or `DELETE_FAILED`. |
| `storageObjectKey` | string, nullable | Random opaque key; present only while an object may exist. Never a public URL. |
| `fileName`, `mimeType`, `sizeBytes` | string/string/integer, nullable | Sanitized response metadata; set only after successful storage. |
| `retentionHoursSnapshot` | integer enum, nullable | The account setting read when the download becomes ready; use the same allowed values as the account. |
| `completedAt`, `expiresAt` | datetime, nullable | Set atomically with `READY`; `expiresAt = completedAt + retentionHoursSnapshot`. |
| `failureCode` | string, nullable | Safe application error code only; no raw provider text, URL, token, or command arguments. |
| `replayOfId` | UUID/string, nullable | Optional link to the history record from which this download was requested again. |
| `createdAt`, `updatedAt` | datetime | UTC timestamps. |

**Relationships**: Each record belongs to one account. A record may reference
the earlier history row that initiated a re-download.

**Indexes**: `(userId, createdAt)`, `(status, createdAt)`, and `(status,
expiresAt)`. Add uniqueness or job-claim constraints only where supported by the
chosen MySQL deployment.

## Download State Transitions

```text
QUEUED -> PROCESSING -> READY
                    -> FAILED
READY -> MEDIA_DELETED   (user removes file; history remains)
READY -> EXPIRED         (retention elapsed; history remains)
READY -> DELETE_FAILED   (object deletion failed; access remains denied after expiry)
DELETE_FAILED -> EXPIRED (retry succeeds)
```

- Only `READY` with `expiresAt > now` may be downloaded.
- Claim and state transitions must be conditional/idempotent so retrying a job
  cannot publish duplicate history rows or overwrite a different user's object.
- When a job succeeds, snapshot the then-current account retention setting, not
  the setting from when the job was queued.
- Manual media deletion removes the object and changes state to `MEDIA_DELETED`;
  it does not remove the history row.
- Automatic expiry removes the object and changes state to `EXPIRED`; the record
  remains visible without a file.
- Deleting a history row also deletes its associated object before removing the
  row. If object deletion fails, retain the row and retry rather than orphaning
  private media.
- On expiry deletion failure, deny access immediately based on `expiresAt`, keep
  the row and object key for retry, and never disclose the object key.

## Persistence Notes

- Prisma owns relational persistence and migrations; repositories map Prisma
  models to existing domain types instead of exposing Prisma types to services.
- Object bytes live only in a private S3-compatible bucket with server-side
  encryption. The database stores opaque keys and minimal metadata.
- The bucket has no public-read policy. The backend streams files only after
  authentication, ownership, status, and expiry checks.
- Temporary download files and extractor artifacts live in private per-job
  directories and are removed after upload or failure.
- Do not store extractor JSON, cookies, raw command lines, or signed storage URLs
  in history or application logs.
